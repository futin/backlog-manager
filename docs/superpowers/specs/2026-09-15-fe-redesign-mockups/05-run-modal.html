The run modal — what a History row opens

Spec §6.1 adopts the dashboard's sidecar modal (290 px facts column, body right, 16 px radius, one shell lift, scrim everywhere) for the run detail without drawing it. This is that drawing, holding everything RunDetail renders today for a finished run, on a run chosen to exercise every reading at once: a merge-mode run the classifier downgraded to branch mode mid-queue, one item merged before the downgrade, one branched after it with a fix loop and a decided question, one parked after two fix loops with a failed verification, one skipped. Added 2026-09-15 by the functionality audit (00-functionality-audit.md). Not a pick-screen — there is one shape, the dashboard's.

Run modal · finished run, opened from History

Drawn at full height so every reading is visible; in the app the body scrolls inside the shell. Max width 1080 px, calc(100vw / var(--font-scale) - 48px) below; full-screen under 700 px with the facts column folding above the body. Escape and the scrim close it (useDialogEscape, one owner). A live run never opens here — its card on the Runs page carries the controls — so the modal has no RunControls.

  • Facts column is RunDetail's head, stacked: project (dot + name), run id, started / finished / wall (runWallMs), status chip (runStatusChip — a crashed run never opens here, it is a live card), mode pill only for branch mode / branch mode (downgraded) with mergeModeNote under it when downgraded, question mode, $ · turns · sessions (runUsageTotals, absent when no usage), then today's chips — merged · branched (when > 0) · skipped · attention · fix loops — as a two-column list, then the attention entries with their questions. The "fifteen stage chips" spec §6.1 first described do not exist today and are not added.
  • Body order is today's: Machine time by stage (StageBars over runStageTotals — seven rows, pipeline order, — for a stage never recorded), Branches to merge (one git merge --no-ff <branch> per branched item, only when any), Items, and Attention — the last folded into the facts column here because the sidecar has one, and the questions under each entry come with it.
  • Each item: id, title, stage chip (glyph + word, toned by STAGE_TONE), RowTime (span · finish clock for a terminal stage, span elapsed otherwise, nothing for skipped / ungroomed, — for pending); the queue … · preflight … lead; the stage track (§4.3) with its ×N fix-loop pill and the terminal node reading the finish clock in --ink2; the per-item usage line (itemUsageTotals; sessions only when > 1); the assumed list (decide mode); the last verification as a disclosure — command, ok / failed, its tail — open by default when failed.
  • Verification tails come from the archived run file, fetched when the modal opens (fetchArchivedRun); until it lands the disclosure shows the command and verdict only, and if the fetch fails a line reads couldn't load verification output under the facts.
  • Parked item's track: the seventh node reads the run's effective exit (branched here, because the run was downgraded before this item) — stepperTerminal answers item-first, run-mode second, so task-30's node still says merged.
  • Not here: Pause / Cancel / Resume (live cards only), the crashed note (live card), the live-only active / queued chips.
