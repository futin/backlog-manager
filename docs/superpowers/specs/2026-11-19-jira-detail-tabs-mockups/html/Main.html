[BE] Calendar settings: store the Default search per user

StatusDone
AssigneeAndreja Jevtic
SprintSP-04-Nov
ParentTIMIFY-26078
Deliverydevelop · draftdemo · draft
Agentidle · 5 ended

Goal. Each user chooses in Calendar settings which contact search the booking form and the fast booking widget open with. The calendar settings get one more element to store that choice.

Build

  • One new element in the user's calendar settings: Default search. It's stored per user and per account, and saved and read together with the other settings of the panel.
  • Five values: name (Name, surname or company), email, mobile number, birthday, external ID.
  • A user who never chose gets the name search.
  • The value stays stored when the plan changes. After a downgrade the frontend decides what applies, so the choice is there again after an upgrade.
  • No QA of its own. The value is tested through the FE story.

Documentation: Calendar Settings §4.10.4

Acceptance criteria

  • The frontend can save and read the Default search with the other calendar settings.
  • Without a stored value, the name search is returned.
  • Two users of the same account keep separate values, and so does one user on two accounts.
