Ledger

Everything the page says today, set as two tables under a one-line head. No new readings and no new chrome: the head is the current three sentences on one line, the watched runs get real columns and a header row, and the activity log gains a kind column it has never had — the payload already carries kind, the page has only ever printed detail. The "watchdog:" prefix the strip needs is dropped here because the column header carries the word.

Console

recommended

Three tiles state the sweeper, the watched set and the policy, in the same tile idiom Runs mode already uses. Each running run is a card with a freshness meter: the heartbeat age drawn against the 15-minute stale line, with a tick at 9.5 minutes where a beat is due — so a run is seen drifting toward crashed before the strip calls it. A crashed card adds attempt pips and how much of the grace window is left before the sweeper may try again. Activity is the same kind-badged table as A. Every new reading is derived on the client from fields already on the wire: updatedAt against RUN_STALE_MS, lastSpawnAt plus graceMs, nextTickAt over tickMs.

C

Timeline

B's head and cards, then the day's sweeper events laid on lanes — one for the sweeper's own arm/idle beats, one per run it ever acted on — with the kind glyphs as the marks and the table beneath as the record. It answers "what has the watchdog been doing today" in one look and shows attempt spacing against the grace window. Marks a minute apart — the failed attempt and its retry at 14:06 and 14:07 — stack rather than overprint, and the real implementation needs the same rule. The honest caveat: the feed holds fifty events in API memory, so on most afternoons this chart is three dots; its value is highest on exactly the bad days.
